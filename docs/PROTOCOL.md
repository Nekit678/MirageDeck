# Протокол профиля N4 Pro

## HID identity

| Поле | Значение |
| --- | --- |
| VID / PID | `5548:1021` (N4ProE, Global) |
| Usage page / usage | `FFA0:0001` |
| Manufacturer | `HOTSPOTEKUSB` |
| Product | `HOTSPOTEKUSB HID DEMO` |
| Firmware response | `V4.N4 Pro E.02.009` |
| Input payload | 512 байт |
| Output payload | 1024 байта |

Основные input/output reports не имеют явного report ID. Windows HID API всё
равно добавляет ведущий нулевой ID, поэтому размеры пользовательских буферов —
513 и 1025 байт. Внутри драйвера payload хранится в аппаратном виде 512/1024.

К оригинальной Input/Output-части descriptor добавлен unnumbered feature report
для чтения панелью перехваченных пакетов. Входные события панель передаёт через
обычный Output report с magic `MBVE`; драйвер отличает его от команд `CRT`.
Точные длины обоих буферов панель получает через `HidP_GetCaps`.
На границе UMDF `mshidumdf` может представить нулевой report ID как значение
`1` (длину вспомогательного буфера); драйвер нормализует оба варианта.
Очереди находятся в драйвере, поэтому короткий burst пакетов с изображением не
теряется, если UI занят отрисовкой.

## Входные события

Обычное событие имеет заголовок:

```text
41 43 4B 00 00 4F 4B 00 00 <hardware-code> <state> 00 ...
 A  C  K        O  K
```

`state=01` — нажатие, `00` — отпускание. Клавиши используют `01..0A`.
Энкодеры:

| № | press | left | right |
| ---: | ---: | ---: | ---: |
| 1 | `37` | `A0` | `A1` |
| 2 | `35` | `50` | `51` |
| 3 | `33` | `90` | `91` |
| 4 | `36` | `70` | `71` |

Touch point использует заголовок `ACK 00 ARX`; координаты big-endian находятся
в байтах 10–13. Свайпы влево/вправо — hardware code `38`/`39`.

## Выходные команды

Командный packet начинается с `CRT 00 00`.

| Команда | Параметры |
| --- | --- |
| `BAT` | bytes 8–11: длина big-endian, byte 12: image slot |
| `LOG` | bytes 8–11: длина background stream |
| `BGPIC` | bytes 10–13: длина background frame; далее geometry |
| `LIG` | byte 10: яркость |
| `CLE` | byte 11: slot или `FF` для всех |
| `DIS` | включить экран |
| `STP` | применить/обновить кадр |

После `BAT`, `LOG` или `BGPIC` идут чистые байты изображения, разбитые на
1024-байтовые packets. Последний packet дополнен нулями, которые не входят в
объявленную длину.

Image slots основных кнопок в экранном порядке:

```text
11 12 13 14 15
 6  7  8  9 10
```

## Добавление трассировки неизвестной команды

Временно поставьте breakpoint или логирование на `UnknownCommandUpdate` в
`MainForm.Apply`. Полный packet уже сохранён внутри update. Не следует искать
новую команду по нулевому padding: сначала сопоставьте поток с одним действием
Stream Dock (одна кнопка, один новый PNG), затем добавьте тест в
`Mirabox.Emulator.Core.Tests` и только после него расширяйте decoder.

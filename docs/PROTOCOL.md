# Протокол профиля N4 Pro

## HID identity

| Поле | Значение |
| --- | --- |
| VID / PID | `5548:1021` (N4ProE, Global) |
| Usage page / usage | `FFA0:0001` |
| Manufacturer | `HOTSPOTEKUSB` |
| Product | `HOTSPOTEKUSB HID DEMO` |
| Firmware response | `V4.N4 Pro E.02.009` |
| Input payload | 512 байт |
| Output payload | 1024 байта |

Основные input/output reports не имеют явного report ID. Windows HID API всё
равно добавляет ведущий нулевой ID, поэтому размеры пользовательских буферов —
513 и 1025 байт. На границе HIDClass ↔ UMDF этот байт уже удалён: минидрайвер
получает и возвращает payload в аппаратном виде 512/1024.

К оригинальной Input/Output-части descriptor добавлен unnumbered feature report
для чтения панелью перехваченных пакетов. Входные события панель передаёт через
`HidD_SetOutputReport` с magic `MBVE`; драйвер отличает его от команд `CRT`.
Точные длины обоих буферов панель получает через `HidP_GetCaps`. Для записи
unnumbered Output report драйвер читает входную WDF memory напрямую: служебный
канал `mshidumdf` для report ID в этом случае имеет нулевую длину, поэтому
`STATUS_BUFFER_TOO_SMALL` при его получении является ожидаемым и не прерывает
чтение основного input-buffer.
Очереди находятся в драйвере, поэтому короткий burst пакетов с изображением не
теряется, если UI занят отрисовкой.

## Входные события

Обычное событие имеет заголовок:

```text
41 43 4B 00 00 4F 4B 00 00 <hardware-code> <state> 00 ...
 A  C  K        O  K
```

`state=01` — нажатие, `00` — отпускание. Клавиши используют `01..0A`.
Энкодеры:

| № | press | left | right |
| ---: | ---: | ---: | ---: |
| 1 | `37` | `A0` | `A1` |
| 2 | `35` | `50` | `51` |
| 3 | `33` | `90` | `91` |
| 4 | `36` | `70` | `71` |

Энкодер отправляет только одиночное событие нажатия с `state=01`; отдельного
release-пакета физический N4 Pro не формирует. В Button Mode четыре экранные
области отправляют одиночные события `40..43` с `state=00`.

Touch point использует заголовок `ACK 00 ARX`; координаты big-endian находятся
в байтах 10–13. В Touchbar Mode Stream Dock распознаёт короткий одиночный
контакт как нажатие элемента, а последовательность точек — как прокрутку.
Виртуальная панель откладывает одиночную точку до отпускания мыши, а поток
координат начинает после порога движения, чтобы небольшой дрейф курсора при
клике не сдвигал содержимое. В Button Mode касание обрабатывается как одна из
четырёх экранных областей, а свайпы влево/вправо имеют hardware code `38`/`39`.
У физического N4 Pro
вертикальный свайп обрабатывается локально прошивкой и отдельного input-кода не
имеет, поэтому эмулятор не может переключить radio button приложения через HID.
Режим виртуальной панели выбирается выходной командой `MOD` либо типом слоя,
который загружает Stream Dock.

## Выходные команды

Командный packet начинается с `CRT 00 00`.

| Команда | Параметры |
| --- | --- |
| `BAT` | bytes 8–11: длина big-endian, byte 12: image slot |
| `LOG` | bytes 8–11: длина background stream |
| `BGPIC` | bytes 10–13: длина background frame; далее geometry |
| `MOD` | byte 10: ASCII `1` — Button Mode, `2` — Touchbar Mode |
| `LIG` | byte 10: яркость |
| `CLE` | byte 11: slot или `FF` для всех |
| `DIS` | включить экран |
| `STP` | применить/обновить кадр |

После `BAT`, `LOG` или `BGPIC` идут чистые байты изображения, разбитые на
1024-байтовые packets. Последний packet дополнен нулями, которые не входят в
объявленную длину.

Image slots основных кнопок в экранном порядке:

```text
11 12 13 14 15
 6  7  8  9 10
```

## Добавление трассировки неизвестной команды

Временно поставьте breakpoint или логирование на `UnknownCommandUpdate` в
`MainForm.Apply`. Полный packet уже сохранён внутри update. Не следует искать
новую команду по нулевому padding: сначала сопоставьте поток с одним действием
Stream Dock (одна кнопка, один новый PNG), затем добавьте тест в
`Mirabox.Emulator.Core.Tests` и только после него расширяйте decoder.
